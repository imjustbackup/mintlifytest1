LEMON Manuals MCP is a self-hosted server — you run it alongside your own LEMON/CHARM manual archive. There is no hosted version. You own the infrastructure, the index files, and the backend that serves manual pages. This guide walks you through everything from cloning the repository to registering the server with your AI client.

## Prerequisites

Before you start, make sure you have the following in place:

- **[Bun](https://bun.sh) runtime** — Bun is the JavaScript runtime used to install dependencies and run the server. Install it from [bun.sh](https://bun.sh) if you don't have it already.
- **A running `lemon-website` backend** — The MCP server fetches manual page content from a live `lemon-website` instance. This is the HTML manual server from the `kubernetes/apps/lemon-manuals/` home-lab repo. The MCP server needs HTTP reach to it.
- **Vehicle index files** — `lemon-index.json` and `charm-index.json` are large index files (~147 MB combined) that the server loads at startup. You fetch them from the cluster (see [Fetching Index Files](#fetching-index-files) below). They are not included in the repository.

## Installation

Clone the repository and install dependencies:

```bash
git clone https://github.com/imjustbackup/lemon-manuals-mcp
cd lemon-manuals-mcp
bun install
```

## Fetching Index Files

The server requires `lemon-index.json` and `charm-index.json` to be present in the `data/` directory. These files are gitignored because they are ~147 MB and can be re-fetched from your cluster at any time.

Pull them from your running `lemon-website` deployment with `kubectl`:

```bash
kubectl -n lemon-manuals exec deploy/lemon-website -- cat /data/lemon/index.json > data/lemon-index.json
kubectl -n lemon-manuals exec deploy/lemon-website -- cat /data/charm/index.json > data/charm-index.json
```

Once fetched, the server loads both files at startup and holds the full ~305,000 vehicle index in memory for fast lookups (~200 ms load time).

You can override the default file paths with the `LEMON_INDEX_JSON` and `CHARM_INDEX_JSON` environment variables if you store the files elsewhere.

## Connecting to the Backend

The server fetches manual page content from `lemon-website` at runtime. Set the `LEMON_BASE_URL` environment variable to point at your backend:

```bash
export LEMON_BASE_URL=http://your-lemon-backend:8080
```

The default value is `http://127.0.0.1:18080`, which matches the local port-forward below. For local development, forward the cluster service to your machine:

```bash
kubectl -n lemon-manuals port-forward deploy/lemon-website 18080:8080
```

Leave that running in a separate terminal while you work with the MCP server.

## Running the Server

Start the MCP server with Bun:

```bash
bun src/index.ts
```

The server listens on `http://127.0.0.1:8787` and exposes two endpoints:

| Endpoint   | Purpose                                                         |
|------------|-----------------------------------------------------------------|
| `/mcp`     | Streamable HTTP MCP endpoint — point your AI client here       |
| `/healthz` | Returns `200 ok` when the server is up and indexes are loaded  |

You should see startup output similar to:

```
[lemon-mcp] loading vehicle indexes: .../data/lemon-index.json, .../data/charm-index.json
[lemon-mcp] 305000 vehicles loaded in 198ms; pages via http://127.0.0.1:18080
[lemon-mcp] streamable HTTP on http://127.0.0.1:8787/mcp
```

You can also control the port with the `PORT` environment variable and the data directory with `LEMON_DATA_DIR` (default: `./data`).

## Registering with Claude

Once the server is running, register it with Claude using the `claude mcp add` command:

```bash
claude mcp add --transport http lemon-manuals http://127.0.0.1:8787/mcp
```

Claude will now have access to all five MCP tools: `list_makes`, `search_vehicles`, `get_page`, `search_manual`, and `get_image`.

<Note>
  The server is stateless — each MCP request creates a fresh transport. Multiple AI clients can connect to the same running server instance simultaneously without interfering with each other.
</Note>
